Troubleshooting record

Initial observation

The web container and Nginx container appeared to have old creation times, which led to an investigation into whether Docker Compose was recreating the services correctly.

The application image was inspected and compared with the image referenced by the running web container.

The image and container IDs matched, confirming that the running web container was using the image available locally.

Root cause of the failed CI/CD deployment

The production workflow initially failed at the deploy-to-ec2 job with:

dial tcp ...:22: i/o timeout
Error: Process completed with exit code 1

The failure occurred while appleboy/ssh-action was attempting to establish the SSH connection to EC2.

The SSH action itself was not the underlying Docker problem. The EC2 SSH connection details, particularly the workflow's server connection configuration, needed to be verified and corrected.

After the connection configuration was updated, the complete GitHub Actions workflow succeeded.

Final deployment result

A production test change was committed and pushed to main. GitHub Actions then:

Built and tested the application.

Built and pushed the Docker image.

Connected to EC2.

Pulled the latest image.

Ran Docker Compose.

Recreated the web container.

Left the application running successfully behind Nginx.
